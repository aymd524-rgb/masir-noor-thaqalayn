# راه‌اندازی متن کامل مصحف

نمایشگر مصحف در مسیر `/quran/mushaf` از صفحه‌بندی ۶۰۴ صفحه‌ای مصحف مدینه استفاده می‌کند. متن صفحات از Quran Foundation Content API دریافت می‌شود و برای امنیت، کلید محرمانه فقط در Supabase Edge Function قرار می‌گیرد.

## پیش‌نیاز دسترسی به قرآن کامل

Quran Foundation در محیط Pre-live فقط سوره‌های حمد و بقره را برای آزمایش در دسترس می‌گذارد. برای دریافت همه صفحات، باید دسترسی Production به Content API تأیید شده باشد. این درخواست و تأیید از سمت صاحب حساب پروژه انجام می‌شود.

## تنظیمات محرمانه Supabase

در Supabase Dashboard پروژه، بخش **Edge Functions → Secrets** را باز کنید و این متغیرها را اضافه کنید:

- `QF_CLIENT_ID`: شناسه برنامه Backend/server در Quran Foundation
- `QF_CLIENT_SECRET`: رمز محرمانه همان برنامه (فقط در Secrets؛ هرگز در GitHub، فایل VITE_ یا مرورگر قرار نگیرد)
- `QF_ENV`: مقدار `production` برای متن کامل
- `QF_SCOPE`: مقدار `content.quran.read` برای دسترسی‌های جدید granular؛ اگر مجوز قدیمی شما `content` است، مقدار آن را `content` قرار دهید.

برای دریافت مجوز، از برنامه Backend/server استفاده کنید؛ برنامه Frontend/mobile به‌تنهایی client secret و دسترسی Content API ندارد.

## انتشار تابع

تابع موجود در این پوشه:

`supabase/functions/mushaf-page/index.ts`

نام تابع: `mushaf-page`

تنظیم `verify_jwt = false` برای این تابع است، چون متن قرآن عمومی است و کاربر باید بتواند پیش از ورود هم مصحف را بخواند. تابع فقط درخواست GET صفحه ۱ تا ۶۰۴ را می‌پذیرد و هیچ عملیات نوشتن یا داده شخصی ندارد. پاسخ‌ها با cache کوتاه‌مدت مرورگر و cache بلندتر edge ارسال می‌شوند.

پس از تنظیم Secrets، تابع را در پروژه Supabase منتشر کنید. در حال حاضر این فایل‌ها در شاخه Git هستند؛ انتشار تابع روی پروژه زنده جداگانه انجام می‌شود و با commit کردن کد به‌تنهایی فعال نمی‌شود.

## آزمون پس از انتشار

1. در محیط Production، صفحه ۱ را باز کنید و بررسی کنید آیات سوره حمد دیده می‌شوند.
2. صفحه ۲ و یک صفحه میانی (مثلاً ۲۵۵) را باز کنید.
3. صفحه ۶۰۴ را باز کنید و کنترل کنید متن، شماره آیات و سطرها نمایش داده شوند.
4. اگر پاسخ 502 دریافت شد، Secrets، محیط Production و مجوز scope را بررسی کنید. خطای 403 معمولاً نشان‌دهنده مجوز یا scope ناکافی است.

**یادآوری:** دسترسی Production، شرایط استفاده و محدودیت‌های API را باید در حساب Quran Foundation تأیید کرد. این مستندات هیچ کلید یا مجوزی را ایجاد نمی‌کند و هزینه/سهمیه سرویس‌دهندگان را تضمین نمی‌کند.
