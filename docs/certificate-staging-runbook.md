# اجرای امن گواهی‌ها در محیط آزمایشی (Staging)

این راهنما فقط برای **پروژهٔ Supabase آزمایشی جدا از تولید** است. migrationها را در پروژهٔ اصلی اجرا نکنید.

## پیش‌نیازها

- PR شمارهٔ ۱۱ (مؤسسه‌ها، عضویت‌ها، کلاس‌ها و ثبت‌نام) باید بازبینی و در محیط آزمایشی اجرا شده باشد.
- از staging یک snapshot/backup قابل‌بازگردانی داشته باشید.
- دسترسی به SQL Editor staging با نقش دارای مجوز migration فراهم باشد.
- حساب‌های آزمایشی مستقل داشته باشید: مدیر مؤسسه، استاد همان کلاس، استاد مؤسسهٔ دیگر، دانش‌پژوه ثبت‌نام‌شده و دانش‌پژوه مؤسسهٔ دیگر.
- هیچ اطلاعات واقعی دانش‌آموز یا امضای واقعی را برای تست وارد نکنید.

## ترتیب فایل‌ها

در staging و فقط پس از بررسی وابستگی‌ها:

1. `supabase/migrations/20261127110000_create_institute_certificates_and_teacher_signatures.sql`
2. `supabase/migrations/20261127120000_add_certificate_issue_revoke_rpcs.sql`

اجرای migrationها باید از مسیر migration runner مورد استفادهٔ پروژه انجام شود؛ از اجرای دستی تکه‌تکهٔ فایل‌ها اجتناب کنید. اگر migration runner در staging قابل استفاده نیست، ابتدا مسیر استاندارد پروژه را مشخص کنید و سپس اجرا کنید.

## Preflight

پس از اجرای migrationها، فایل زیر را در SQL Editor staging اجرا کنید:

`docs/certificate-staging-preflight.sql`

نتیجهٔ مورد انتظار: یک ردیف با مقدار `certificate_staging_preflight_passed`.

اگر هر خطایی رخ داد:
- تست را متوقف کنید.
- خروجی خطا را ثبت کنید.
- هیچ policy یا grant را برای «سبز کردن» تست به‌صورت موقت حذف نکنید.
- migrationها را روی تولید اجرا نکنید.

## آزمون‌های ضروری با حساب‌های آزمایشی

1. استادِ تخصیص‌یافته به کلاس، پس از تأیید دستی تکمیل دوره، بتواند یک گواهی صادر کند.
2. صدور دوباره برای همان enrollment رد شود.
3. استادِ کلاس دیگر و استاد مؤسسهٔ دیگر نتوانند گواهی را صادر یا ابطال کنند.
4. دانش‌پژوه فقط گواهی خودش را ببیند؛ شناسهٔ گواهی دانش‌پژوه دیگر را امتحان کنید و باید دسترسی رد شود.
5. دانش‌پژوه نتواند گواهی صادر، ویرایش یا حذف کند.
6. محتوای snapshot گواهی پس از صدور قابل تغییر نباشد.
7. امضای استاد در bucket خصوصی باشد؛ کاربر ناشناس نتواند آن را بخواند.
8. استاد نتواند امضای کاربر دیگر را بارگذاری، جایگزین یا حذف کند.
9. ابطال فقط یک بار انجام شود؛ پس از ابطال، گواهی با وضعیت «باطل» نمایش داده شود.
10. گواهی بدون امضا نیز قابل صدور باشد، اگر امضا انتخاب نشده باشد.
11. چاپ / Save as PDF روی Android بررسی شود: متن فارسی، شکل حروف، حاشیه و تصویر امضا.
12. عضویت تعلیق‌شده یا enrollment نامعتبر، صدور گواهی را مسدود کند.

## معیار توقف

تا وقتی همهٔ آزمون‌های دسترسی بین مؤسسه‌ها، صدور تکراری، دسترسی مستقیم به Storage و چاپ موبایل موفق نشده‌اند، PR را ادغام یا migration را روی تولید اجرا نکنید.

این راهنما اجرای تست را انجام نمی‌دهد و هیچ تغییری در دیتابیس ایجاد نمی‌کند.
