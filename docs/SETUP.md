# راه‌اندازی و اتصال

## ۱) تنظیم Supabase

در داشبورد پروژه Supabase، آدرس پروژه (Project URL) و کلید Publishable را از بخش API Keys دریافت کنید.

این دو متغیر را در محیط اجرای برنامه تنظیم کنید:

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_REPLACE_ME
```

در Lovable یا میزبان دیگر، بخش Environment Variables / Secrets پروژه را باز کنید، هر متغیر را جداگانه اضافه کنید و سپس Preview یا Deployment را دوباره Build کنید. اگر نام منو در نسخه رابط کاربری متفاوت است، از راهنمای همان میزبان پیروی کنید.

**مهم:** کلید عمومی Publishable برای کد مرورگر است؛ کلید `service_role` یا `sb_secret` را هرگز وارد متغیرهای `VITE_*` نکنید. هر متغیری با پیشوند `VITE_` ممکن است در خروجی مرورگر قابل مشاهده باشد.

## ۲) کنترل اتصال

پس از Build مجدد، صفحه حساب یا بخش اتصال را باز کنید. اگر هر دو متغیر شناخته شوند، برنامه از حالت Demo به حالت Backend تغییر می‌کند. در غیر این صورت ممکن است همچنان داده‌های نمونه دیده شوند.

## ۳) امنیت پایگاه داده

- RLS باید فعال بماند.
- هرگز برای رفع خطای دسترسی، سیاست‌ها را عمومی یا ضعیف نکنید.
- عملیات حساس باید با حساب کاربر واردشده و سیاست‌های سمت پایگاه داده کنترل شود.
- کلیدهای محرمانه فقط در سرور امن و هرگز در مرورگر استفاده می‌شوند.

## ۴) وضعیت همگام‌سازی کد

مخزن GitHub زیر نسخه کدِ نگهداری‌شده را نشان می‌دهد:

https://github.com/aymd524-rgb/masir-noor-thaqalayn

اتصال خودکار دوطرفه Lovable و GitHub را بدون بررسی commitها فرض نکنید. در زمان آخرین بررسی، شاخه `main` از commit جدیدتری نسبت به commit ثبت‌شده در اطلاعات پروژه Lovable برخوردار بود؛ بنابراین پیش از ویرایش یا انتشار از Lovable، وضعیت اتصال و آخرین commit را در داشبورد بررسی کنید تا تغییرات یکدیگر را بازنویسی نکنند.

## ۵) بررسی پیش از انتشار

1. Build در GitHub Actions موفق باشد.
2. متغیرهای Supabase در محیط اجرا تنظیم شده باشند.
3. ورود، خروج و بازیابی نشست با حساب آزمایشی بررسی شود.
4. نقش‌های دانش‌پژوه، استاد و مدیر جداگانه آزمایش شوند.
5. محدودیت دسترسی هر نقش و سیاست‌های RLS آزمایش شوند.
6. ثبت‌نام، حضور و غیاب و نمره‌دهی با داده آزمایشی کنترل شوند.
7. پس از بررسی، نسخه نهایی منتشر شود.

موفقیت Build به‌تنهایی اثبات‌کننده اتصال Backend، صحت ورود یا آماده‌بودن انتشار نیست.

## ۶) متن و نمایش مصحف قرآن

بخش مصحف فعلی هنوز نسخه نهایی نیست: فقط دو صفحه نمونه در مخزن وجود دارد و صفحه‌های دیگر عمداً متن آیه نشان نمی‌دهند. این رفتار باید حفظ شود تا متن ناقص یا تولیدشده به‌اشتباه قرآن تلقی نشود.

برای هدف «مانند مصحف مدینه/عثمان‌طه» دو شیوه را نباید با هم اشتباه گرفت:

- **QPC Hafs / Unicode**: راه‌اندازی ساده‌تر با متن Unicode و قلم UthmanicHafs؛ برای نمایش آیات درون برنامه مناسب است، اما به‌تنهایی تضمین‌کننده صفحه‌بندی کاملاً یکسان با مصحف چاپی نیست.
- **QCF V2**: نمایش مبتنی بر کدهای گلیف و قلم اختصاصی هر صفحه؛ مستندات Quran Foundation آن را گزینه مناسب برای نمایش پیکسلی و دقیق صفحه‌های مصحف معرفی می‌کند. برای هدف صفحه‌بندی دقیق، این مسیر باید بررسی و پیاده‌سازی شود.

منبع فنی:
- راهنمای رسمی قلم و نمایش مصحف: https://api-docs.quran.com/docs/tutorials/fonts/font-rendering/
- راهنمای رسمی API: https://api-docs.quran.com/docs/quickstart/
- شرایط توسعه‌دهندگان Quran Foundation: https://api-docs.quran.com/legal/developer-terms/

**الزامات امنیت و مجوز برای اتصال API:**
1. API فعلی Quran Foundation از OAuth2 سمت سرور استفاده می‌کند؛ شناسه و به‌ویژه `client_secret` نباید در مرورگر یا متغیرهای `VITE_*` قرار گیرند.
2. توکن و درخواست‌های محتوای قرآن باید از سرور امن یا تابع سروری عبور کنند؛ کلید محرمانه هرگز در GitHub commit نشود.
3. شرایط استفاده، نمایش محتوای قرآن را در تجربه کاربر برنامه مجاز می‌داند، اما بازنشر جداگانه داده خام یا بسته داده نیازمند مجوز کتبی جداگانه است.
4. طبق شرایط جاری، نگهداری محتوای API بیش از یک هفته محدود است، مگر آنکه از مسیر مجاز Content Sync و مطابق الزام همگام‌سازی استفاده شود. بنابراین snapshot ثابت فعلی را نباید راهکار آفلاین/نهایی فرض کرد.
5. متن قرآن نباید ویرایش، بازسازی یا با هوش مصنوعی تولید شود. پس از اتصال منبع، باید شماره صفحه، سطرها، قلم و متن با مصحف مرجع بررسی شوند.
6. پیش از انتشار عمومی، سیاست حریم خصوصی و شرایط استفاده برنامه نیز باید منتشر شوند.

تا زمان فراهم شدن مجوز/دسترسی و اتصال امن سرور، منبع فعال باید در حالت نمونه نمایشی باقی بماند و برچسب نمونه روی صفحات حفظ شود.
